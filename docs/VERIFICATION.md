# 0.5.0 验证范围

本记录区分实现、自动检查、实际 GUI 操作和仍待验证的行为。测试使用自有合成音频，不包含用户录音或作品。

## 0.5.0 新增验证

- 32 组核心检查、98 项实际编辑模型断言通过；以下旧版功能包含在回归中。
- 副本格式矩阵覆盖 8/11.025/12/16/22.05/24/32/44.1/48/96 kHz、单/双声道的可用选项；实际写入并回读编码、位深、采样率、声道、帧数和样本误差。原件保持不变，同路径副本被拒绝。
- 原生 NSSavePanel 附件通过程序化控件动作验证：默认源格式、选择格式、同步文件名与扩展名、无源默认 WAV24、隐藏不可用格式。这不等同于真人保存窗口端到端验收。
- 删除的 44.1/48/96 kHz 单/双声道矩阵通过：最长 15 ms 重叠，未混入删除内容，接缝外样本不变、同相信号不额外增益、标记按保留内容迁移、WAV 保存回读。固定阶跃测试相邻样本最大跳变小于 0.003。
- 删除开头的淡入端点、长度、声道关系、短片段自适应通过；极短/全选/删除末尾、一次撤销/重做、Delete 键、剪切剪贴板原样本通过。
- 修复解码器提前返回部分缓冲时，单声道 Float WAV 被误判为不完整；多次读取填满缓存块，1 秒多采样率单声道浮点文件精确回读通过。
- 编码边界：当前系统 FLAC 少于 4608 帧不能通过回读，已排除该副本选项并保留写入保护；32 kHz MP3 本机解码返回 EOF，暂不列入副本选项。AAC 32 kHz 使用每声道 96 kbps，44.1/48 kHz 使用每声道 128 kbps；96 kHz 不提供 AAC/MP3。
- 极短文件的 AAC/MP3/ALAC 保存回读及 FLAC 失败保留已有目标通过。
- 使用建议正文保留；个人建议未加入公开源集。本轮采用代码、GitHub API 和 Git，未执行 GUI 自动化；真实素材主观听感仍待试听。

## 0.4.0 已有验证

- 27 组核心检查、72 项实际编辑模型断言通过。
- WAV 整数/浮点位深、真实 AIFF 容器、AAC、ALAC、FLAC、MP3 CBR/VBR 的已测试组合支持源编码回读。系统能读的其他格式不能据此推定均可写。
- 完整文件覆盖/副本、原件外部变更检测、临时写入与回读、WAV 成功后才移源文件到废纸篓、冲突及失败保护。
- 选区增益内部倍率正确，选区外逐帧不变，边界保持原幅度并在约 15 ms 内平滑过渡；多次滚轮调整仅形成一次撤销。
- 44.1/48/96 kHz 单/双声道片段转换为 48 kHz / 24-bit / 双声道；输出帧数按时长四舍五入，首尾 720 帧淡化，短片段自适应。
- 96 kHz 中 30 kHz 测试信号降为 48 kHz 后残留 RMS < 0.005；440 Hz 中段幅度误差 < 0.015。
- 原生文件承诺的后台写入回调真实生成 WAV，并回读确认格式、时长和淡化端点；这不等同于 Finder 拖放已通过 GUI 验收。
- 建议 Markdown 同版重开保留，升级只改版本头，正文不丢；导入 Markdown 追加。
- 普通滚轮指针锚定、连续小数帧缩放、Shift/横向滚动平移；导航不修改音频或选区。
- GUI 实测：中文建议输入/关闭/退出再开保留，旋钮滚轮调音量/点击提交/撤销，指针横向缩放及反向还原，标题栏最大化；前版三个文件动作实际保存回读通过。
- 本机 release 构建、Info.plist 及严格签名检查通过。测试环境为 Apple Silicon / macOS 27.2.1 / Swift 6.4.2。
- 开源前从 Git 暂存区的 44 个公开文件创建独立目录，重新编译 LAME 和应用；27 组核心与 72 项模型检查再次通过，未使用原工作区的构建缓存或已安装 LAME。

## 待验证与限制

- Finder 跨窗口音频/Markdown 拖入、片段拖出落盘：自动化尝试没有完成端到端落盘，需真人复核。
- 主观音质、播放中快速滚轮增益调整、真实声卡/麦克风录音、无缝循环边界、保存面板真人键盘输入。
- 极短片段会缩短 15 ms 淡化/衔接；1–2 帧音量选区保持原幅度，避免制造新的端点不连续。
- 元数据、封面、BWF 和文件内标记不保留；内部 Float32；有损格式重新编码；无崩溃恢复。
- 早期一小时合成立体声峰值 RSS 约 1.33 GiB，不能代替真实长录音验收。
- CI 配置覆盖应用构建、核心检查和签名验证，不覆盖硬件、GUI 或主观听感。

## 复现

按 [README](../README.md) 构建后执行 CoreChecks 和 WorkflowChecks。检查程序遇到失败返回非零状态。额外的 `CoreChecks --long` 会生成约 1.38 GB 的长音频缓存，不属于常规快速检查。
